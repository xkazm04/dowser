## What the run says about Dowser

1. **No cross-lens de-duplication.** Card 4 (opportunity) is the union of cards 13-15 (security-cra). The run
   judged it "not a duplicate of any one of them" and kept it. One goal took 4 of 15 slots, and the budget cut real
   items for it (sharing kept cards, per-lens limit, owner-only `~/.dowser` permissions).
2. **Deferring to another lens can lose the fix.** Doc drift dropped the PAGE-13 correction because a security card
   "covers the same contradiction", but card 12 changes the code and leaves the page wrong. A deferral should
   check that the other card's Done fixes this lens's object.
3. **Verify checks that a quote exists, not that it supports the claim.** Card 13's padding passes verify.
   Relevance is a judging-step concern (SKILL.md section 6) or a lens evidence rule ("every evidence row is named
   in Description").
4. **Dowser's own monorepo gap hit Dowser.** Security ran `partial` because `forge/package-lock.json` and
   `forge/static/app/package-lock.json` were not audited. That is the same gap as card 2, now with first-party
   evidence.
5. **UX friction filled 3 of 4 slots.** It left DOW-50 (empty Learning tab) and DOW-65 (where Accept files the
   issue) unexamined in its report. Worth a look when ux-friction next changes.
